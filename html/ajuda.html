1. Preparar o computador

O percurso começa no README.md do repositório, visível no navegador antes de instalar seja o que for. Aí encontra a instalação de Git, WSL 2 e Docker Desktop para Windows 11, a clonagem e o arranque deste site.

O URL do repositório ainda não foi fornecido. Por isso, este site não apresenta uma ligação de clonagem inventada. Se recebeu apenas estes ficheiros, abra README.md no Bloco de Notas ou peça ao responsável o endereço do repositório.

Qual é a janela certa?

Abra Iniciar, procure PowerShell e escolha Windows PowerShell. Para abrir como administrador, use o botão direito → Executar como administrador. Os comandos desta página usam a janela normal.

Para abrir o PowerShell na pasta certa, entre na pasta que contém o compose.yaml do manual no Explorador de Ficheiros, clique com o botão direito numa zona vazia e escolha Abrir no Terminal. Use um separador PowerShell.

2. Controlar o manual

O botão Copiar copia apenas o comando. Leia a indicação da pasta, cole no PowerShell e prima Enter. Sem JavaScript ou permissão de cópia, pode selecionar o texto e usar Ctrl+C.

Confirmar o motor Docker

Onde: PowerShell normal, em qualquer pasta. Administrador: não.

docker version

Resultado esperado: secções Client e Server. Se faltar Server e aparecer erro, abra Docker Desktop e aguarde.

Iniciar ou voltar a iniciar

Onde: PowerShell normal, na pasta do compose.yaml deste manual. Administrador: não.

docker compose up -d

Resultado esperado: serviço manual iniciado. Na primeira vez, aguarde pelo download da imagem.

Depois abra http://localhost:8080. Pode fechar o PowerShell quando o comando terminar.

Ver o estado

Onde: PowerShell normal, na pasta do compose.yaml deste manual. Administrador: não.

docker compose ps

Resultado esperado: manual com estado Up e porta 127.0.0.1:8080. Este resultado é mostrado no terminal, não verificado pelo site.

Parar

Onde: PowerShell normal, na pasta do compose.yaml deste manual. Administrador: não.

docker compose stop

Resultado esperado: serviço manual parado. Esta página deixa de poder ser recarregada até voltar a iniciar o serviço.

Consultar as mensagens

Onde: PowerShell normal, na pasta do compose.yaml deste manual. Administrador: não.

docker compose logs --tail 50 manual

Resultado esperado: mensagens recentes do Nginx para ajudar a identificar o problema.

Estes comandos não controlam LocalGPT, Open WebUI nem PrivateGPT.

3. Resolver problemas

O Docker não consegue ligar ao motor

Abra Docker Desktop e aguarde que indique o motor em execução. Se o erro persistir, consulte a atualização do WSL no README. Depois de um reinício do Windows, pode ser necessário abrir novamente o Docker.

O comando não encontra o ficheiro de configuração

Abra o terminal na pasta que contém o compose.yaml deste manual, junto da pasta html. Uma janela aberta noutra pasta não encontra automaticamente o projeto.

A porta 8080 já está ocupada

Outra aplicação pode estar a usar a porta ou o Windows pode tê-la reservado. Peça ajuda para identificar a origem. Se reconhecer a aplicação, feche-a normalmente e tente de novo. Não termine processos desconhecidos.

Há uma mensagem sobre virtualização

Use Ctrl+Shift+Esc → Desempenho → CPU e verifique «Virtualização». Se estiver desativada, siga a documentação do fabricante do computador ou peça apoio informático. As instruções BIOS/UEFI variam entre equipamentos.

O download parece demorar

Imagens e modelos podem ser grandes. Aguarde e observe o terminal. Uma mensagem de erro de rede exige verificar a ligação, proxy ou VPN; o manual não pode estimar o tempo restante.

Copiar não funciona

Em caso de recusa pelo navegador, o manual seleciona o comando e apresenta uma indicação para usar Ctrl+C. Também pode selecionar o texto manualmente. Em dispositivos táteis, mantenha o dedo sobre o texto e use a opção de cópia do navegador.

Abro localhost no telemóvel e não vejo o manual

Localhost aponta para o dispositivo onde está o navegador. Este manual está acessível apenas no computador que o serve. Pode testar o formato móvel reduzindo a janela do navegador nesse computador.

Como pedir ajuda?

Indique a solução, o passo, o comando e a mensagem exata, bem como as versões instaladas e o hardware. Remova palavras-passe, tokens e conteúdo privado antes de partilhar registos.

4. Termos úteis

Modelo / LLM
Programa treinado para interpretar texto e gerar respostas. Precisa de ficheiros de modelo e recursos para funcionar.
Ollama
Aplicação que disponibiliza modelos no computador, usada nas receitas de referência.
Embeddings
Representações numéricas de texto usadas para encontrar informação relacionada com a pergunta.
Indexação / ingestão
Leitura e preparação dos documentos para pesquisa. É necessário esperar que termine.
Contentor
Ambiente gerido pelo Docker onde uma aplicação é executada.
Porta
Número no endereço que distingue serviços. Neste manual, é 8080.
Volume
Armazenamento de dados de uma aplicação Docker que deve ser preservado.

5. Trabalhar localmente

A intenção destes guias é executar os modelos no computador. Os downloads iniciais requerem internet e podem ocorrer também na primeira indexação ou pergunta, conforme a aplicação.

  1. Confirme com o responsável que o modelo de conversa e os componentes de pesquisa usam serviços locais.
  2. Descarregue todos os modelos e dependências da configuração aprovada.
  3. Processe um documento de teste sem dados privados e confirme a resposta.
  4. Para validar funcionamento sem internet, desligue a ligação e repita o teste, incluindo um reinício das aplicações.

Este ensaio confirma apenas o funcionamento offline do percurso testado; não constitui uma auditoria de tráfego ou de privacidade. O site não monitoriza os serviços. Os guias só devem ser considerados concluídos depois de resolver as etapas pendentes.

Materiais do projeto consultados

Na pasta vizinha LocalGPT/localGPT foram lidos o Compose, documentação e componentes da interface. O exemplo Exemplo/TP1_IS_Entrega forneceu o README das três instalações e a configuração PrivateGPT. Estas pastas não são necessárias para abrir o manual e não estão incluídas nele.

Para concluir os guias

  • LocalGPT: commit com as correções, configuração e modelos finais, hardware, ligação ao Ollama e teste de indexação.
  • Open WebUI: versão fixa, instalação com persistência, seleção dos modelos locais e sequência de Knowledge e contexto na interface.
  • PrivateGPT: perfil exclusivamente local coerente, imagem e montagem dos dados, porta sem conflito, ingestão e teste após reinício.
  • Todos: um documento de exemplo não confidencial, resposta esperada e resultado após reinício e sem internet.

O registo dos testes do site está em VALIDACAO.md, junto do README no repositório. O manual não apresenta um indicador de disponibilidade das aplicações porque não tem integração com elas.
