Este guia distingue o que está nos materiais do projeto do que falta testar. Não avance sobre etapas pendentes. O arranque do manual não instala Open WebUI.

PASSO 01

O que é

O Open WebUI fornece uma interface web de conversa. Na receita deste projeto, comunica com Ollama instalado no computador e usa documentos como contexto para as respostas.

Uma interface local não garante, por si só, que o modelo também seja local. É necessário confirmar a origem do modelo e dos embeddings na configuração efetiva.

PASSO 02

Requisitos específicos

  • Windows 11 e Docker Desktop operacional, conforme o README.
  • Ollama local, com os modelos descarregados e acessíveis a partir do contentor.
  • Espaço para a imagem, modelos e documentos, e memória compatível com os modelos escolhidos.
Por completar com a configuração testada

Fixar a versão do Open WebUI e os requisitos de hardware medidos. A receita encontrada usa a porta 3010 para a interface; confirmar que está livre e que será mantida.

PASSO 03

Instalação

  1. Prepare Git, WSL 2 e Docker Desktop seguindo o README.
  2. Consulte a instalação oficial do Ollama no Windows para preparar o serviço local.
  3. Obtenha a receita Docker aprovada antes de criar o contentor.

O exemplo usa a imagem ghcr.io/open-webui/open-webui:main e o nome is-tp1-openwebui. A etiqueta main muda ao longo do tempo e a receita apresentada não declara armazenamento persistente.

Por completar com a configuração testada

Fornecer uma versão fixa e o comando ou Compose testado, incluindo volume de dados, ligação ao Ollama e porta vinculada apenas ao computador. Não se publica aqui um comando de instalação incompleto.

PASSO 04

Configuração do modelo

A receita declara llama3.2:3b para conversa e nomic-embed-text para embeddings. Aponta o Ollama para http://host.docker.internal:11434, o endereço usado pelos contentores para alcançar o serviço no Windows.

Estes nomes são evidência do exemplo; ainda falta confirmar a seleção efetiva na interface, incluindo o motor de embeddings. A referência a RAG_FULL_CONTEXT=true também precisa de ser reproduzida na versão escolhida.

Por completar com a configuração testada

Registar o download dos modelos, os campos e menus exatos para escolher Ollama local e embeddings locais, a desativação de ligações externas e a configuração de contexto. Confirmar que a ligação contentor→Ollama funciona no Windows.

PASSO 05

Arranque e acesso

O exemplo aponta para http://localhost:3010, depois de o contentor arrancar. Descreve a criação de uma primeira conta de administrador local. Guarde as credenciais dessa conta.

Por completar com a configuração testada

Acrescentar o comando de arranque inicial e o percurso de criação da conta na versão fixa. Verificar a interface e a seleção do modelo local antes de permitir carregar documentos. O manual não sabe se esse endereço está ativo.

PASSO 06

Carregamento de documentos

O exemplo descreve a criação de uma coleção Knowledge (conhecimento), com os documentos de referência.

  1. Comece com um documento pequeno e sem dados confidenciais.
  2. Na instalação validada, crie a coleção e carregue o documento seguindo os menus que o responsável confirmar.
  3. Aguarde pela conclusão do processamento.
  4. Associe explicitamente a coleção à conversa antes de perguntar.
Por completar com a configuração testada

Documentar o caminho exato dos menus, formatos aceites, sinal de fim de processamento e associação da coleção à conversa. Os seis documentos referidos no exemplo não são distribuídos com este manual.

PASSO 07

Primeira pergunta

Depois de confirmar que o modelo local está selecionado e que a coleção está associada, escreva:

Qual é o assunto principal do documento associado? Apresenta dois factos e indica a fonte de cada um.

Abra as referências apresentadas e compare-as com o documento. Se a resposta ignorar o ficheiro, confirme a associação da coleção e o fim do processamento.

Por completar com a configuração testada

Guardar uma resposta de teste com fontes e confirmar que todos os modelos funcionam localmente, depois dos downloads necessários.

PASSO 08

Parar e voltar a iniciar

Apenas para uma instalação existente que use o nome do contentor indicado no exemplo. Estes comandos não criam nem configuram uma instalação nova.

Onde: PowerShell normal, em qualquer pasta. Administrador: não.

docker stop is-tp1-openwebui

Resultado esperado: o contentor existente para; o comando apresenta o seu nome.

Noutro dia, abra Docker Desktop e Ollama, aguarde, e execute:

Onde: PowerShell normal, em qualquer pasta. Administrador: não.

docker start is-tp1-openwebui

Resultado esperado: o mesmo contentor volta a iniciar; após ficar pronto, abra localhost:3010.

Parar não remove o contentor. A persistência após remoção ou atualização ainda não está definida; não o elimine para resolver um problema. Ollama continua a funcionar separadamente.

Por completar com a configuração testada

Adaptar estes comandos se a instalação final usar Compose ou outro nome e confirmar que as contas, documentos e conversas sobrevivem a um reinício.

PASSO 09

Problemas frequentes

Não aparece nenhum modelo

Confirme que Ollama está aberto, os modelos foram descarregados e a ligação configurada aponta para o serviço local. A lista vazia não se resolve escolhendo um fornecedor externo.

A resposta não usa os documentos

Confirme o processamento da coleção, a sua associação à conversa e a configuração dos embeddings. O contexto referido no exemplo ainda precisa de validação na versão escolhida.

A página não abre

Confirme o Docker e a porta da instalação final. O endereço 8080 é o manual; a receita do Open WebUI aponta para 3010.

Onde: PowerShell normal, em qualquer pasta, apenas se existir o contentor com este nome. Administrador: não.

docker logs --tail 50 is-tp1-openwebui

Resultado esperado: últimas mensagens do contentor. Se indicar que não existe, confirme o nome na receita aprovada.
